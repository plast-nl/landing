# Робота над сайтом Пласту в Нідерландах

## Принципи змін

- Один коміт — одна логічна, завершена зміна.
- Пов’язані шаблони, стилі, JavaScript і тексти змінюємо разом,
  якщо вони потрібні для однієї функції.
- Незалежні виправлення оформлюємо окремими комітами.
- Перед комітом переглядаємо зміни та додаємо лише відповідні файли.
- Не змінюємо сторонні напрацювання без необхідності.

Довідка: https://gitbybit.com/uk/gitopedia/best-practices/atomic-commits

## Погодження та GitHub

- Перед комітом показуємо запропоноване повідомлення й чекаємо погодження.
- Перед публікацією опису PR або коментаря показуємо його текст
  і чекаємо погодження.
- Повідомлення комітів, описи PR та коментарі пишемо українською,
  стисло й без персональних формулювань.
- Виконуємо commit, push, деплой або злиття лише в погодженому обсязі.
- Не переписуємо опубліковану історію без окремого погодження.

## Гілки та публікація

- Працюємо в погодженій гілці. Поточна гілка розробки — redesign.
- Нові задачі починаємо від актуальної погодженої базової гілки.
- Один PR охоплює одну цілісну задачу й може містити кілька комітів.
- Перед злиттям у main перевіряємо результат на beta.
- Успішна збірка або release workflow ще не підтверджують,
  що нова версія доступна за публічною адресою — це перевіряємо окремо.

## Перевірка

- Для змін шаблонів, стилів або конфігурації перевіряємо збірку Jekyll.
- Перевіряємо відповідні посилання та функції.
- Зміни інтерфейсу перевіряємо на комп’ютері та реальних мобільних пристроях.
- У звіті зазначаємо підтверджені пристрої, браузери й середовище.
- Не подаємо заплановані або автоматичні перевірки як виконані вручну.

## Поточний дизайн

- Зберігаємо український контент і просту багатосторінкову структуру.
- Використовуємо зелені акценти та адаптивну навігацію.
- Логотип: 96 px на широких екранах, 64 px нижче 992 px.
- Для декоративних символів використовуємо SVG, щоб уникати emoji
  та відмінностей між пристроями.

## Внутрішні матеріали

- AGENTS.md та внутрішні посібники не публікуємо у збірці сайту.
- Документацію, не пов’язану з конкретною зміною коду,
  оформлюємо окремо.
